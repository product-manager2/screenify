I changed requests 2 and 3 and left request 1 alone. I couldn't build, typecheck or run anything here, so none of it has been tested.

**1. Export to CSV: no change.** People already have this. Selecting rows shows an "Export {objectLabel}" command in the selection command menu. It is defined in `standard-command-menu-item.constant.ts` and handled by `ExportRecordsCommand.tsx`. It exports only the selected rows, because `useRecordIndexLazyFetchRecords.ts` filters on the selected IDs, and it needs the existing `EXPORT_CSV` permission. The screenshot library doesn't show this command. The rows-selected capture only lists Send Email, Update and a more-actions button. I didn't add a second export button, so it may be hidden under that more-actions menu.

**2. Copy an address.** In `useGetSecondaryFieldButton.ts`, address fields now return a hover copy button. It copies the address as displayed, using `formatAddressDisplay`, so it follows the field's sub-field settings. It shows an "Address copied to clipboard" toast. The same hook feeds the companies table cells and the inline fields on a company page, so both get the button. There's no button on an empty address. I didn't add an "open in maps" action.

**3. Record count.** `RecordIndexPageHeader.tsx` now fetches the total count for the current view filters. `RecordIndexPageHeaderTitle.tsx` shows it in the lighter tertiary text next to the title, for example "People 5". While rows are selected it still shows "N selected". I added a separate count query instead of reusing the existing selection-count effect, because that effect skips fetching when rows are selected and would give wrong numbers. This costs one extra small query. I didn't add tests or touch the translation catalogs. The new "Address copied to clipboard" string is uncompiled and needs the usual extract step.
